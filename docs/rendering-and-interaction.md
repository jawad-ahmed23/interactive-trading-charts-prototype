# Rendering & Interaction

Observed behaviour (O-numbers from `architecture-overview.md`) mapped to concrete algorithms. The
renderer is **Lightweight Charts v5** (verified against **v5.3.0**, released 2026-11-10). This doc gives
the math so we know what LWC does for us and what we add as plugins.

Classification key: **VERIFIED** (LWC typings/source or official docs confirm) · **INFERRED**
(observed on the reference platform, not independently confirmable) · **DESIGN** (our decision).

---

## 1. Layer stack
> **Confidence:** two canvases per cell observed (INFERRED for purpose). LWC layer/z-order facts VERIFIED. Redraw scheduling is DESIGN based on LWC's model.

Observed (O16): a table grid with one row per pane and cells for axes and pane. **Each cell holds two
stacked canvases.** LWC uses the same structure.

| z | Layer | Redraw trigger | Who draws |
|---|---|---|---|
| 0 | Background, grid, session shading | scale change, resize | LWC + our `SessionShadingPrimitive` (`zOrder() → 'bottom'`) |
| 1 | Series (candles, lines, histograms) | data or scale change | LWC series / our custom series |
| 2 | Drawings, marks, price lines | data, scale or drawing edit | our primitives (`zOrder() → 'normal'`) |
| 3 | Crosshair | pointer move | LWC |
| 4 | Above-crosshair overlays (drag previews) | pointer move | our primitives with `zOrder() → 'top'`. In LWC, 'top' draws **above** the crosshair (VERIFIED) |

The point of the split: **pointer moves repaint only the top canvas**. Moving the crosshair never
re-rasterises candles.

### Redraw strategy (DESIGN, matching LWC)
- A mutation calls `invalidate(level)` with level ∈ {Cursor, Light, Full}. Invalidations are **merged** (max level) and flushed once per `requestAnimationFrame`.
- Cursor → top canvas only. Light → the series canvas of the affected pane. Full → all panes and axes (resize, timeframe change, scale-mode change).
- Realtime ticks (O10, about 1/s) produce Light invalidations. Several ticks in one frame produce one paint.

### DPI handling (VERIFIED)
LWC handles `devicePixelRatio` itself. It binds each canvas to its `device-pixel-content-box` size
through `fancy-canvas` and re-sizes on DPR change. Plugin renderers draw through
`target.useBitmapCoordinateSpace(scope => …)` (bitmap pixels: snap lines with
`Math.round(x * scope.horizontalPixelRatio) + 0.5` for odd widths) or `useMediaCoordinateSpace` (CSS pixels).

## 2. Time scale (index-based)
> **Confidence:** index-based axis VERIFIED (LWC logical indexes). The reference platform's index-based bars and server-computed label levels are INFERRED (O5–O7). Option names and defaults VERIFIED (v5.3.0).

Bars are addressed by a **dense logical index**: the bar's position in the union of all series' times.
Missing times create no gap; only whitespace items (`{ time }` with no values) create gaps.

### Index → x (LWC model, simplified)
```
x(i) = W − rightOffsetPx − (lastIndex − i) · barSpacing − barSpacing/2
rightOffsetPx = timeScale.rightOffsetPixels ?? timeScale.rightOffset · barSpacing
```
- `barSpacing` default **6** px, clamped to `[minBarSpacing (default 0.5), maxBarSpacing (default 0 = no limit)]`.
- `rightOffset` default **0** bars. `rightOffsetPixels` (v5, optional) takes priority over it.
- Inverse (bar under the cursor): `i = lastIndex − (W − rightOffsetPx − barSpacing/2 − x) / barSpacing`, rounded. LWC exposes this as `timeScale().coordinateToLogical(x)`.

All scroll and zoom operations change the **visible logical range** `{from, to}`
(`getVisibleLogicalRange` / `setVisibleLogicalRange`).

### Tick-mark (label) selection
LWC computes label importance per bar from its time. The levels are **internal and not part of the
public API**. Per the v5.3.0 source they are: <1 s, second, 1/5/30-minute, 1/3/6/12-hour, day, month,
year. **There is no week level.** Label selection is greedy from the most important level down. A label is kept
if it is at least `ceil(maxLabelWidth / barSpacing)` bars away from labels already kept (VERIFIED, source).

What we control (public API): `timeScale.tickMarkFormatter(time, tickMarkType, locale)`. `tickMarkType`
is the public `TickMarkType` (Year, Month, DayOfMonth, Time, TimeWithSeconds). We use it to format labels
in the **instrument's exchange timezone** (LWC formats in UTC by default).

The reference platform also labels "future" positions right of the last bar (O6, INFERRED). LWC
labels only real or whitespace points. To show future labels, append **whitespace bars** generated by
`SessionCalendar.futureBarTimes()` (DESIGN, phase 2).

## 3. Price scale
> **Confidence:** modes, defaults and options VERIFIED (v5.3.0). Nice-step algorithm is DESIGN (for our own axis-related features; LWC computes its own labels).

### Auto-scale
```
visible = bars with index in [floor(from), ceil(to)]
lo = min(low of visible bars over all auto-scaled series/primitives on this scale)
hi = max(high …)
padding: if lo == hi → expand by 1 % (or one tick) each side
top    = hi + (hi − lo) · marginTop    / (1 − marginTop − marginBottom)
bottom = lo − (hi − lo) · marginBottom / (1 − marginTop − marginBottom)
```
- `scaleMargins` default `{ top: 0.2, bottom: 0.1 }`; values outside 0–1 throw (VERIFIED).
- `autoScale` default `true`. Overlay scales (`priceScaleId: ''` or a custom id) are always auto-scaled (VERIFIED).
- Volume overlay: a custom `priceScaleId` with margins `{ top: 0.8, bottom: 0 }` (DESIGN; matches the bottom-of-pane volume in screenshots).
- Fixed ranges (RSI 0–100) use the series option `autoscaleInfoProvider` (VERIFIED).
- O18: the scale re-fits as the visible range changes. Dragging the price axis turns auto-scale off.

### y mapping per mode (`PriceScaleMode`, VERIFIED: Normal=0, Logarithmic=1, Percentage=2, IndexedTo100=3)
| Mode | value → y |
|---|---|
| Normal | `y = H · (top − v)/(top − bottom)` |
| Logarithmic | `y = H · (log(top) − log(v)) / (log(top) − log(bottom))` (LWC applies an internal shift for values near 0) |
| Percentage | `v' = (v − base)/base · 100`, base = first visible value; then Normal |
| IndexedTo100 | `v' = v/base · 100`; then Normal |

### "Nice" step for our own axis-related features (DESIGN)
```
rawStep = (top − bottom) / (H / 30)
mag = 10^floor(log10(rawStep));  m = rawStep / mag
step = (m ≤ 1 ? 1 : m ≤ 2 ? 2 : m ≤ 2.5 ? 2.5 : m ≤ 5 ? 5 : 10) · mag
step = max(step, instrument.tickSize)
```
Price formatting comes from `Instrument.pricePrecision` / `tickSize`. Fractional instruments use
`priceFormat: { type: 'custom', formatter }`. Volume uses K/M/B suffixes.

### Last-price label with countdown (O19, INFERRED; implementation DESIGN)
A series primitive's `priceAxisViews` draws a second line with `closeTime − serverNow` as `mm:ss`
(`hh:mm:ss` for ≥ 1 h). A 1 s timer calls `requestUpdate()`, which triggers a light repaint.

## 4. Scroll and zoom
> **Confidence:** LWC behaviours VERIFIED (v5.3.0 typings + source). Reference-platform zoom anchoring INFERRED (O17, screenshot hint). Kinetic decay constant is DESIGN.

### Zoom (wheel, pinch, axis drag)
LWC behaviour (VERIFIED):
- `handleScale: { mouseWheel: true, pinch: true, axisPressedMouseMove: { time: true, price: true }, axisDoubleClickReset: { time: true, price: true } }` (all default true).
- **Wheel zoom anchors at the cursor's x** by default. With `timeScale.rightBarStaysOnScroll: true` (default **false**), LWC skips the right-offset correction, so zoom effectively anchors at the **right edge / last bar**.
- A horizontal wheel delta (`deltaX`) scrolls rather than zooms.

Anchor math (LWC model, for our tests):
```
zoom(anchorX, scale):                      // scale > 1 zooms in
  anchor = coordinateToLogical(anchorX)
  newSpacing = clamp(barSpacing · scale, minBarSpacing, maxBarSpacing || ∞)
  shift the visible range so `anchor` keeps its x
```

**Our default (DESIGN, matching O17):** right-edge anchored. Set `rightBarStaysOnScroll: true` and toggle
it to `false` while ⌘/Ctrl is held (`keydown`/`keyup` → `applyOptions`), so the modifier gives
cursor-anchored zoom. No custom wheel handler is needed.

### Pan (VERIFIED options; DESIGN mapping)
- `handleScroll: { mouseWheel, pressedMouseMove, horzTouchDrag, vertTouchDrag }`, all default true.
- Drag right by `dx` px moves the view `dx / barSpacing` bars into history.
- Price-axis drag scales vertically and turns off auto-scale. Double-click on the axis restores it (`axisDoubleClickReset`).

### Kinetic scrolling
`kineticScroll` defaults: `{ touch: true, mouse: false }` (VERIFIED). We enable `mouse: true` (DESIGN).
LWC's decay is internal. Our tests assert only "continues after release, then stops, and any pointerdown stops it".

### Reset and scroll to realtime (O18)
- **Reset view** shortcut → `timeScale().resetTimeScale()` and `priceScale('right').applyOptions({ autoScale: true })` (VERIFIED methods).
- A "scroll to realtime" button, shown when the last bar is off-screen → `timeScale().scrollToRealTime()` (VERIFIED).
- **Live-edge follow:** `shiftVisibleRangeOnNewBar` (default **true**, VERIFIED). If the realtime edge is visible, a new bar shifts the view by one bar. Otherwise the view stays still.

### Load more at the left edge (O12)
`timeScale().subscribeVisibleLogicalRangeChange(range => …)` (VERIFIED). LWC's own infinite-history
tutorial triggers at `range.from < 10`. We use a threshold of **50 bars** for earlier prefetch (DESIGN).
Algorithm in `data-feed-spec.md §4.2`. View preservation after prepending N bars:
```
r = timeScale().getVisibleLogicalRange()
series.setData(merged)            // validated: ascending, unique times (see §8)
timeScale().setVisibleLogicalRange({ from: r.from + N, to: r.to + N })
```

## 5. Crosshair, legend, panes
> **Confidence:** API facts VERIFIED (v5.3.0). Legend fallback behaviour is DESIGN.

- **Crosshair:** `CrosshairMode` = Normal(0), Magnet(1), Hidden(2), MagnetOHLC(3); **default Magnet** (VERIFIED). Magnet snaps to the series' main value (close). **We use MagnetOHLC** so y snaps to the nearest of O/H/L/C (DESIGN). The crosshair draws on the top layer only.
- **Legend:** DOM over the canvas, fed by `chart.subscribeCrosshairMove(param => param.seriesData.get(series))` (VERIFIED). It shows the hovered bar's OHLC and each indicator's value, and the **last bar** when the cursor leaves (DESIGN).
- **Sync API:** `chart.setCrosshairPosition(price, time, series)` and `clearCrosshairPosition()` (VERIFIED), used by multi-chart crosshair sync.
- **Multi-pane (v5 native, VERIFIED):** `chart.addSeries(def, opts, paneIndex)`, `chart.panes()`, `addPane()`, `removePane()`, `swapPanes()`. Per pane: `setStretchFactor`/`getStretchFactor`, `setHeight`, `moveTo`, `attachPrimitive`. Separator drag-resize is enabled by `layout.panes.enableResize` (default true). We store pane sizes as **stretch factors** so layouts survive window resizes.
- All panes share **one time scale**. Each pane has its own price scales (left, right, overlays).

## 6. Chart types and transforms
> **Confidence:** native LWC series VERIFIED. Heikin-Ashi formula VERIFIED (StockCharts ChartSchool). Renko construction VERIFIED as the common convention (StockCharts: ATR(14) box, 2-box reversal). Range/line-break are DESIGN.

Candles, bars (OHLC), line, area, baseline and histogram are **native LWC series** (`CandlestickSeries`,
`BarSeries`, `LineSeries`, `AreaSeries`, `BaselineSeries`, `HistogramSeries`). Transformed types are
computed in our `bars` module and fed to a standard series.

### Heikin-Ashi
```
haClose = (o + h + l + c) / 4
haOpen  = i == 0 ? (o + c) / 2 : (haOpen[i−1] + haClose[i−1]) / 2
haHigh  = max(h, haOpen, haClose);  haLow = min(l, haOpen, haClose)
```
Same time index as the source. The live bar is recomputed on every tick from the committed `haOpen[i−1]`.

### Renko (box size B: fixed, or ATR(14) computed at load; reversal = R boxes, default 2)
```
state: lastClose (top of last up brick or bottom of last down brick), dir
on each source close c:
  while dir==up   and c ≥ lastClose + B:          emit up brick [lastClose, lastClose+B];   lastClose += B
  while dir==up   and c ≤ lastClose − R·B:        first down brick starts at lastClose − B; dir = down; …
  (mirror for dir == down)
```
**Bricks are not time-aligned.** Each gets a synthetic, strictly increasing time (source time plus a
sub-second counter), with a lookup table back to source time for labels. Close-based is the default.
High/low-based is an option.

### Range bars (range R), line break (N=3), Point & Figure, Kagi
Event-driven construction from prices, with synthetic times like Renko. Phase 3+.

## 7. Drawing tools
> **Confidence:** DESIGN. `ISeriesPrimitive.hitTest` and pane primitives VERIFIED (v5.3.0).

### Data model, anchored in data space, not pixels
```ts
interface Drawing {
  id: string;
  type: 'trendline' | 'horizontal' | 'ray' | 'fibRetracement' | 'rectangle' | 'text' | 'arrow' | 'channel' | 'measure';
  instrumentId: InstrumentId;          // drawings follow the instrument, not the timeframe
  points: { time: number; price: number }[];   // time = UTC seconds; may be past the last bar
  style: { color: string; width: number; dash: number[] };
  locked: boolean;
  visibleOn: Timeframe[] | 'all';
  zOrder: number;
  paneId: 'main' | string;
}
```
- **Time → x on any timeframe:** binary search for the bar containing `time`. Interpolate fractionally inside that bar's duration. For a time past the last bar: `x = x(lastIndex) + calendar.barsBetween(lastBar.time, time, timeframe) · barSpacing`.
- Storing time (not index) is what keeps a trendline in place after switching `5m` → `1h`.

### Hit-testing
Each drawing implements `hitTest(x, y)` on its primitive (LWC `ISeriesPrimitive.hitTest`, VERIFIED):
- Segment: point-to-segment distance `< 4 px` (6 px on touch). Handles: radius 6 px.
- Iterate in reverse z-order and take the first hit. Use a bounding-box prefilter when there are 100+ drawings.

### Edit state machine
`idle → (tool chosen) placing[k] → … → idle`, and `idle → (pointerdown on handle) dragging → idle`.
The preview draws in a `'top'` z-order view. Commit on pointerup and push an undo/redo command.

### Persistence
Debounced autosave (1 s) through the state store (`indicator-engine-spec.md §8`).

## 8. Data validation before LWC (VERIFIED: needed in production)
LWC's checks for ascending/unique times and numeric values in `setData` run **only in the development
build**. Production silently accepts bad data. Therefore:
- `BarStore` guarantees ascending, unique `time` before any `setData`.
- `none`/`NaN` values are **never** sent. Indicator gaps become whitespace items `{ time }`.
- `series.update(bar)`: an older time **throws** in production, unless called as
  `update(bar, true)` (`historicalUpdate`, v5) for an existing point. The bar-stream contract
  (`data-feed-spec.md §3.1`) drops stale bars before they reach LWC.
